# Публикация на GitHub Pages

Сайт собирается как полностью статический анонимный артефакт: автономный
`play.html` становится `_site/index.html`. Серверная часть, внешние файлы и CDN
не требуются.

## Локальная релизная проверка

```bash
npm ci
npm test
npm run pages
python3 -m http.server 5173 --directory _site
```

После этого сайт доступен на `http://localhost:5173`. Каталог `_site/` является
сборочным артефактом и не добавляется в Git.

## Первый запуск GitHub Pages

1. Создать репозиторий с основной веткой `main` и отправить в него проект.
2. Открыть **Settings → Pages**.
3. В разделе **Build and deployment → Source** выбрать **GitHub Actions**.
4. Запустить workflow `Test and deploy GitHub Pages` вручную или отправить новый
   commit в `main`.
5. Дождаться успешного environment deployment `github-pages`.

Workflow сначала устанавливает зафиксированные зависимости через `npm ci`,
запускает тесты и только затем публикует `_site`. Для deployment выданы только
необходимые разрешения: `contents: read`, `pages: write`, `id-token: write`.

## Анонимность

Релизный артефакт содержит только приложение. Имена автора и организации,
внешние исходные файлы, номера страниц и ссылки на них в сборку не входят.

## Ограничения

- Прогресс хранится в `localStorage` конкретного браузера и origin сайта.
- Смена URL репозитория или пользовательского домена создаст новый origin и
  прежний локальный прогресс автоматически не перенесётся.
- Пользовательский домен и файл `CNAME` не настроены; для стандартного адреса
  `https://<владелец>.github.io/<репозиторий>/` они не нужны.
