# Стандарт содержания и проверки урока

## Карточка задачи

У каждой задачи есть уникальный ID `SXX-QYY`, анонимный номер раздела, полное условие, тема, статус реализации и при наличии несколько подпунктов. Обязательный чеклист:

- [ ] Сверить полное условие в каталоге (дроби, сигмы, индексы, звёздочки, допущения, подпункты).
- [ ] Определить **отличающийся навык / паттерн**. Не давать всем задачам общую лекцию по Бернулли.
- [ ] Записать prerequisite: необходимые базовые навыки, зависимость от недоступного фрагмента лекции.
- [ ] Ввести теорию, обозначения, формулу и её условия применимости (без спойлера босса).
- [ ] Сделать точную интерактивную геометрию / симуляцию / визуализацию либо обоснованный микроэксперимент.
- [ ] Разбить рассуждение на ≥2 атома, каждый проверяет один переход.
- [ ] Поддержать несколько представлений одного ответа (дроби, десятичные, выражения, допустимая точность).
- [ ] Составить подсказки в два уровня: стратегия, более конкретная опора, но не окончательный ответ.
- [ ] Финал должен закрывать **каждый** подпункт источника, а не только «самый интересный».
- [ ] При неверном ответе показать направление исправления, не вычитать XP и не увеличивать тайный штраф.
- [ ] Указать, что автоматическая проверка доказательств — проверка формальных шагов, если она не оценивает текст.
- [ ] Unit tests: формула, границы, округление, неверные выборы, крайние случаи, повторная награда.
- [ ] Обновить контент-статус только после прохождения e2e, открыть на экране ~390px.

## Форматы заданий

- **predict**: прогноз до запуска вероятностного эксперимента.
- **manipulate**: двигать распределение, событие, область; live-обратная связь.
- **number/expression**: числовой ввод, парсер дробей и выражений, контролируемый допуск.
- **construct**: сборка формулы из частей или распределение с ограничениями.
- **counterexample**: построить контрпример неверному утверждению.
- **proof-step**: упорядочить доказательство, завершить леммы; обязательно объяснить необходимость переходов.
- **boss**: исходная задача (все подпункты). Для частично автоматизированных проверок необходим прозрачный критерий.

## Приоритизация реализации

Сначала закладывать **понятийные пререквизиты**, а не обязательно идти строго по номеру страницы. Предлагаемый порядок:

1. Семинар 1: S01-Q01 (независимость), Q03 (урна), Q05 (кубики), Q06 (перестановки), Q08 (попарная независимость), Q09 (включения-исключения), далее Q10–Q11.
2. Семинар 2: Q03–Q04 (условная зависимость), Q05–Q13 (схема Бернулли, суммы, смешивание).
3. Семинар 3: Q01–Q09 и механика блуждания.
4. Остальные последовательно со вспомогательными мини-уроками для необходимых определений.

## Состояния (без подмены)

- `needs_authoring` — задача учтена, но учебная механика не готова; нельзя получить мастерство/XP.
- `ready` — полноценный урок с проверкой; игрок может его пройти.
- `mastered` — состояние конкретного игрока после закрытия финала, не уровень готовности контента.

Регистрируй завершение только после верной финальной проверки. Для многошагового босса используй отдельные суб-состояния всех подпунктов.
